Tightening the system

Stylistic drift accumulating in places the design system already has answers for — units, fonts, sizes, and the grammar of repeated UI elements.

1.1

Pick one unit and commit

styles.css · Board.tsx · multiple

DriftThe system is mostly rem-based via the --space-* scale, but the file is peppered with stray px values: --line-w: 1px, border: 2px solid… in toasts, filter: blur(2px) on the king, 0.03125rem player rules. The 1vw font-size root then makes every px island shift differently from the rest of the UI when the viewport scales.

Fix: Decided rem everywhere. Borders, blur radii, hairlines, the --line-w token — all on the --space-* scale. No px islands.

Lock the type scale

tokens.css declares 4 sizes — styles.css uses ~14 different ones

Drift--text-xs through --text-lg are defined and almost never referenced. Hardcoded sizes proliferate: 0.625, 0.6875, 0.75, 0.8125, 0.875, 0.9375, 1.0625, 1.125, 1.1875, 1.375, 1.5, 1.875, 4.5 rem — at least 13 distinct steps for a UI that should live on five.

1.4

What is the eyebrow actually for?

Home.tsx hero · Modal eyebrow ("New game") · home section headers ("In progress", "Recent")

OpenYou asked a fair question: it's the only sans-serif uppercase element in a Garamond UI, so it stands out — but what is it communicating? Today it does three different jobs:

  • On the home hero, it's a tagline — "The Viking board game of strategy" — sitting above the wordmark like a book's subtitle.
  • On the modal, it's a kicker — "New game" — categorising the dialog so the title (Hotseat / Online / Against AI) doesn't have to.
  • On the home sections, it's a section label — "In progress", "Recent" — that should arguably be a small-caps Garamond header like the right-sidebar's "Moves".

So the answer is: there isn't one semantic role, there are three, and that's why the inconsistency in tracking and weight feels off.

Recommendation: keep it for kicker/categorising work only — exactly where it justifies feeling like a different voice (modal kicker; possibly the hero tagline). Replace the home section headers with the same small-caps Garamond pattern as "Moves" — that's the system's existing label-on-rule grammar. One eyebrow type, used sparingly, plus one section-header type, used everywhere a section opens.

1.5

Two modal grammars in one component

styles.css .modal-body uses auto 1fr, .modal-hint spans 1 / 4

BugThe modal body is a 2-column grid, but .modal-hint tries to span columns 1–4. It works incidentally, and it gives away that the grid grew without the rules being revisited. Combined with .modal-rule being a height-zero borderless ‹hr›, the modal's internal layout is brittle.

Fix: Decided spell the grid as grid-column: 1 / -1, and let the dividing line live as border-top on the row that needs it instead of an empty hr.

ii

Best practices to adopt

Things working today that would survive longer, scale better, or be more accessible with a small change.

2.1

<a onClick> for buttons is a trap

GameLayout.tsx — game-actions, moves-nav · Home.tsx — entry cards

A11yThe Resign / Draw / Undo controls and the « ‹ › » nav are bare <a> tags with no href and an onClick. Screen readers won't announce them as buttons, keyboard users can't tab to them, and the cursor's pointer only happens because of cursor: pointer. The home entry cards have the same shape. navigate("/") happens, but no router prefetch fires.

Fix: Decided Resign/Draw/Undo become <button type="button">; the home entry cards become <button> (they trigger a modal, not a route); the moves-nav becomes <button>. Route-going links like the wordmark and recent games stay as <A>.

Today
<a onClick={resign}>Resign</a>
<a onClick={() => sheet(true)}>…
// not focusable, not announced
// as button, no Enter/Space
Proposed
<button type="button"
onClick={resign}>Resign</button>
// focusable, role=button,
// keyboard activation, free
2.2

The player state is mutually exclusive — make it one prop

GameLayout.tsx

LogicThe classes go like this:

class={`player black${isBlackActive() ? " active" : ""}${!isBlackActive() ? " inactive" : ""}`}

Decided so a player is always either active or inactive. The CSS then has rules for both. Cleaner: a single data-state="active|idle|gameover" attribute. Same outcome, half the conditions, and it lets you target hover / focus / aria states uniformly later.

Today
class=`player black${active
? " active" : ""}${!active
? " inactive" : ""}`
Proposed
class="player black"
data-state={state()}
// "active" | "idle" | "ended"
2.3

Single source of truth for mode actions

GameLayout.tsx — modeActions and modeButtons are identical

SmellThe two lookup tables (desktop and mobile) declare the same arrays but separately, so adding a new action means editing two places and hoping you remember. Same for actionDefs vs toolbarDefs — the difference is one has an icon, the other has a label.

Fix: Decided a single actions map keyed by the action name, with {label, icon, onClick, disabled}, and a single modeActions array per mode. Render either chip or icon-button from the same definition. (Not a design item — noted.)

2.4

Scope the move-history scroll

MoveHistory.tsx

Side-effectcurrentEl.scrollIntoView uses the document scroller as a fallback, so on smaller viewports it can scroll the whole page when a move is jumped to. Scope the scroll to the list container.

// instead of currentEl.scrollIntoView(…)
const top = currentEl.offsetTop - scrollRef.clientHeight / 2;
scrollRef.scrollTo({ top, behavior: "smooth" });
2.5

Audit light-theme contrast on muted text

tokens.css --bk-ink-mute: rgba(60,50,40,0.55) on --color-warm-100

A11yItalic, muted, 0.875rem game-status text on a paper background measures around 4.0:1 against AA's 4.5:1 floor for body text. Same for several eyebrows. The dark theme is fine because the mute is on a much darker page.

Fix: Decided raise --bk-ink-mute light to 0.62, and use --bk-ink-soft instead of --bk-ink-mute for the game status (it's primary information, not a label).

3.4

Recent games as a table of contents

Home.tsx · .recent .game-row

AestheticMockupThe recent-games list reads as standard rows. Render it as a TOC: title left in Garamond, leader dots filling the gap, page-number-style metadata right in italics. Same data, but it reads as chapters in your playing book.

OpenYou flagged: the highlighted “your turn” row's leader dots look almost identical to the section header's underline rule — the eye reads them as the same kind of line. Two ways to disambiguate; pick one.
